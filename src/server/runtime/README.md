# Private runtime composition

`createRuntimeScope()` is lazy: importing it or creating the scope reads no environment and opens no connection. Invoke its returned `withRuntime(async runtime => ...)` once per server request and await the entire callback. It owns a Neon WebSocket `Pool`, bounds connection/query/statement timeouts, validates the authenticated and active database roles using the existing `withTenantTransaction` closure checks, resolves the configured exact host mapping, and closes the pool in `finally`. Nothing falls back to a local database, PGlite, mock credentials or a test environment switch.

`composeRuntime(config, db, fetch)` is the explicit component boundary for offline tests and trusted server composition. It wires Better Auth, access, invitations, students, per-tab practice and the validated persistent Hebcal cache with the trusted numeric verse catalog. It does not independently attest an injected database's role. Production callers use the scoped wrapper. The wrapper's initial mapping check is not an incoming-request authorization check: future auth handlers must call `runtime.resolveHost(actualRequest)` **before** the SDK auth handler, and every application service still checks its live capabilities. This slice adds no handlers, public endpoints, browser harness or provider setup.

## Configuration contract

`loadRuntimeConfig(env)` reads only an explicitly supplied private environment object. The default runtime scope supplies `process.env` when called. Failures use a fixed unavailable error with no cause or input value.

- `PORTAL_ENVIRONMENT`: `production`, `preview` or `local`. If `VERCEL_ENV` is present it must agree (`development` corresponds to `local`); a Vercel process or `NODE_ENV=production` cannot select local mode.
- `PORTAL_DEPLOYMENT`: exact existing `tenant_host.deployment` value, 1–100 ASCII letters/digits/underscores/hyphens. Production requires `production`, matching the seed. Config never creates mappings.
- `BETTER_AUTH_URL`: production is exactly `https://bneimitzvah.centralreform.org`. Preview requires one explicit HTTPS DNS origin, distinct from production and `bneimitzvah.vercel.app`, backed by its own reviewed synthetic database/mapping and separate secrets. Local requires an explicit HTTP `localhost` or `127.0.0.1` origin with port and corresponding local mapping. No trailing slash/path/query/credentials/fragment, wildcard, authenticated infrastructure alias or inferred forwarded-host fallback.
- `DATABASE_URL`: a separately provisioned restricted LOGIN member of `portal_runtime`, never an owner, with an exact Neon `*.neon.tech` hostname and `sslmode=require`; query options other than that single TLS option are rejected. Its actual current/session identity, privileges and transitive memberships are checked before global auth/cache access, rather than trusted from its username. The configured role/database/mapping must already exist; this code provisions nothing.
- `BETTER_AUTH_SECRET`: private high-entropy 32–512 character value, separately configured per environment. A length check cannot establish entropy. Invitation throttle and student preparation/import signing keys use separate HMAC-SHA256 purposes bound to environment, deployment and origin. Rotation invalidates outstanding service bindings and changes throttle key namespaces; plan rotation deliberately.
- `RESEND_API_KEY` and `RESEND_FROM`: sending key and a bare verified sender mailbox. Both are required; missing mail configuration does not silently enable an alternate sign-in transport. Runtime never logs recipient/sender, link, token or provider response.
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`: optional as a pair. Omit both for magic-link-only operation; provider configuration remains a separate setup gate.

Nonempty `DATABASE_MIGRATION_URL` or `BOOTSTRAP_OWNER_EMAIL` is rejected in the runtime process. Operator migrations/bootstrap run separately with their own private environment; do not populate operator values in the runtime deployment or shared local environment. `.env.example` lists names for both process roles only, with no values. Do not serialize this config, services, errors, SQL statements or request objects into responses/logs.

Current [Neon CLI connection-string documentation](https://neon.com/docs/cli/connection-string) includes `channel_binding=require` and sometimes `connect_timeout` in copied URLs. Pinned driver 1.2.0 exposes no channel-binding/SCRAM-PLUS implementation or configuration in its source/types. Its local `CONFIG.md` explains that secure WebSocket TLS is enabled by default while nested PostgreSQL TLS is disabled. For this pinned runtime, prepare a separate reviewed WebSocket runtime URL containing only `sslmode=require`; remove unsupported libpq `channel_binding` and URL timeout options rather than treating them as enforced. The runtime sets its own bounded timeout options. It makes no channel-binding claim. If provider policy requires channel binding, stop setup for a driver/policy review; do not weaken that requirement or use owner credentials. Migration/operator clients can retain their separately supported libpq options.

Mail uses only `POST https://api.resend.com/emails`, omits credentials, rejects redirects and enforces a 5-second default/10-second maximum deadline. It sends plain text, no HTML, tracking metadata or attachments, and discards provider response bodies. Magic links must use the pinned SDK's exact `/api/auth/magic-link/verify` path/32-letter token; invitation links require `/invitations/open` and one 43-character base64url token. Both require the configured canonical origin and unique allowlisted query keys. Magic-link redirect destinations are the explicit relative paths `/`, `/sign-in` and `/invitations/accept`; additional destinations require review when handlers are built. Resend open/click tracking is controlled at the sending-domain level, so the operator must disable both there before real delivery. No per-message disabling claim is made.

The global Hebcal cache stores only bounded normalized date/calendar reading metadata in the existing cache table. Keys encode provider/API version/calendar/date/triennial mode, never a person or tenant. Both database reads and writes reject unknown metadata fields, mismatched request/envelope/date/calendar, invalid verse ranges and malformed timestamps/TTL via the existing reader validation. Upstream fetch remains fixed to the official Hebcal endpoint; no names or contacts enter those requests. The cache is not an assignment or licensed-text store.

The logger creates its own random request UUID and emits only fixed event codes plus allowlisted numeric status. It never accepts metadata objects or serializes errors, causes, headers, bodies, URLs, SQL, mail or tokens. Provider-library logging stays disabled, and pool error events produce only a fixed event. Platform/request infrastructure logging requires a separate deployment review, especially for auth/invitation query strings.

## API evidence and limits

Pinned local `@neondatabase/serverless@1.2.0` README confirms built-in WebSocket support after Node 21 and request-scoped Pool lifetimes; Node 24 supplies WebSocket. Interactive Pool/Drizzle transactions preserve the existing capability transaction contract. Official [Neon driver documentation](https://neon.com/docs/serverless/serverless-driver) distinguishes interactive WebSocket transactions from HTTP. [Resend's send-email reference](https://resend.com/docs/api-reference/emails/send-email) defines the fixed REST endpoint and payload. [Resend's maintained sending guide](https://github.com/resend/resend-skills/blob/main/skills/resend/references/sending/overview.md) documents domain-level tracking. [Hebcal's developer APIs](https://www.hebcal.com/home/developer-apis) remains the public calendar source. The pinned Better Auth magic-link implementation was inspected for its path, token generation and callback query behavior.

Tests use synthetic inputs, in-process mail capture, PGlite component SQL and isolated mocked driver lifecycle failures. They make no live Neon WebSocket, Resend delivery, Google OAuth or production transport claim. No provider was contacted by the tests; no provider was provisioned.
