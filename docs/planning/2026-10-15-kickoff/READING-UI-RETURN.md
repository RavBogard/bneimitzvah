## Contract and surfaces

The assigned tutor sees an inline reading editor below the current confirmed projection. Admin roster rows link to `/workspace/admin/students/:studentId/reading`, using the same editor in explicit admin mode. Parent, student and child-practice projections never mount the editor. All authority remains in the existing reviewed prepare/confirm/read services; no server, schema, auth-core or dependency changes.

This is an Operate extension of the incumbent Annotated score system: existing white field, system typography, fine rules, burgundy actions and restrained notices. Confirmed references stay visibly separate from the proposed replacement. Phone fields stack and real calendar choices wrap; no fake Hebrew, chant or additional settings. No context/init/chooser round was repeated.

Preparation POST sends only explicit staff mode, kind and optional custom references or a server-listed calendar pick. A subsequent authorized assigned-reading GET must match the original displayed student's revision/date and current kind's assignment ID/revision/review flag before either prepared or needs-selection content is exposed. This closes the prepare-against-new-server-state/old-UI race without changing the API DTO. Final local generation/key checks occur after that GET; failure leaves no confirmable proposal. Server confirmation still checks the opaque binding transactionally.

Only actual snapshot choices are offered: full reading, available triennial and individual listed aliyot. Empty Torah/haftarah calendars remain explicit empty states. Custom input preserves ordered lines but the server validates canonical books, ranges and verse limits. Prepared review preserves exact ranges, verse count, calendar availability/timestamp and separately reported maftir; maftir is never silently added. `entryCap` and `nusach` configuration are outside this reading-only confirmation.

Every input change clears the prepared review immediately. Student/role/kind/assignment drift or access revalidation invalidates it without rebinding the draft. The keyed editor remains a sibling of the loading/loaded projection, preserving authorized same-session textarea state; a changed session binding unmounts it. Review bindings live only in component memory, never URLs/logs/storage, and are locally bounded to five minutes from preparation start. Server expiry is authoritative.

Confirmation is explicit, synchronous single-flight and binding-only. No optimistic replacement: the client checks the saved assignment ID/revision against a fresh authoritative read before reporting the current assignment. A known save with failed/different read is distinguished from an uncertain mutation result.409/expired/denied/unknown outcomes discard the review and block further preparation until explicit reload. Focus revalidation does not clear that blocked state or automatically retry a mutation.
