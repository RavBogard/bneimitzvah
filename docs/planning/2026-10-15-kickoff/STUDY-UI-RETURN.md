## Architecture and surface

New `src/components/portal/workspace/study/{api,view,credits}` consumes only the reviewed assigned-text endpoint. Narrow `reading.tsx`, provider and existing-token CSS changes integrate it into the Annotated score workspace. No production server/schema/auth-core/runtime changes. The only shared fixture change is an optional private synthetic `studyLoad` injection; default existing browser fixtures remain unavailable readers.

Metadata remains fast and authoritative. Essential confirmed ranges and `needsReview` precede text; ordered verse references, calendar provenance and historic confirmation dates remain available in the existing disclosure. Text failure never removes the assignment or staff editor. Only the selected confirmed kind is fetched, with explicit Torah/Haftarah choice if both exist; the English edition is fixedJPS2023, with no fake translation picker/audio/drafting tools.

The provider owns `readStudy(baseline,kind,offset,signal)` and keeps practice handles encapsulated. It captures the tab generation, attaches a handle only for explicit child mode and discards late/aborted responses. Client validation requires mode, student ID/live revision, assignment ID/kind/revision/review flag and context stable ID/authority revision/expiry. Returned child student revision agrees with the newly authorized metadata; the original entry revision is not frozen authority.

One mounted text view registers with the reading panel before initial load. Reading reload first clears/aborts text, reads metadata, then explicitly passes that fresh metadata into text revalidation and awaits completion. The existing provider's same-session reload promise therefore cannot reveal a retained text page before revalidation. There is no second fetch-on-render/effect path. Unchanged selected assignments preserve the explicit page offset; changed assignment identity/revision/order resets0. Staff editor state remains independently mounted and retains drafts across authorized same-session checks; changed session binding still discards the whole subtree.

Each text page is recomputed from trusted numeric reference metadata: canonical ranges must re-expand to the exact assigned verse list, and returned refs/count/order/offset/nextOffset/chapter order must match the100-verse/eight-chapter partition. Requests contain only literal mode/kind, known assignment ID/revision, fixed translation and explicit offset. Streamed response size is capped at2MiB and request duration15seconds. Previous/Next and retry are explicit; no prefetch, automatic retries, client storage/service-worker cache or arbitrary references/URLs.

Structured Hebrew renders as escaped React text nodes with `lang=he`, RTL and preserved marks. Written/read alternatives remain separately visible and labeled; paragraph gaps/after-verse meanings are explicit, as is the inverted-nun sign. English is aligned by validated canonical verse keys and stays honestly absent when unavailable. Flattened Hebrew and structured segments must agree. Unexpected segments, malformed Unicode/bidi overrides, unknown fields and inconsistent translation status fail closed.

Credits use a duplicated closed client registry of the reviewed MAM/JPS2023 edition metadata, with exact equality checks. Only those source/license links and a canonical Sefaria chapter link are rendered, using HTTPS/noopener. Creator, license and modification/noncommercial/share-alike notices remain available. No provider HTML/links/diagnostics are interpreted or forwarded as markup.

409 and503 clear old text and show explicit metadata-refresh/unavailable recovery.401/403/404 clear text and the reading projection; a failed authority check during provider revalidation fails that reload. Child denial also clears its active context through the existing provider behavior. Render bindings, aborts and per-view/request generations prevent stale child/mode/student/revision/page results from replacing a new selection. Logout/session failure removes the private subtree.
