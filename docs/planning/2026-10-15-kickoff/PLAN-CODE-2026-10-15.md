## Data model

Every tenant-scoped table carries `tenant_id`; only `src/server/data/` queries them, always with the session's tenant.

| Table | Holds |
|---|---|
| `tenant` | id (`crc`), name, product name ("CRC B'nei Mitzvah"), `customs` jsonb |
| `tenant_host` | hostname → tenant (`bneimitzvah.centralreform.org`, preview and localhost → `crc`) |
| `user`, `account`, `session`, `verification` | Better Auth's own tables |
| `membership` | user × tenant, role `student` / `parent` / `tutor` / `admin`, `is_cantor` |
| `invite` | tenant, email, role, student link, expiry, used_at |
| `student` | tenant, first/last name, b'nei mitzvah date, parent email(s), optional own email, linked user, status |
| `guardian` | student × parent membership |
| `tutor_student` | tutor membership × student |
| `assignment` | student, kind `torah` / `haftarah` / `blessing-before` / `blessing-after`, `ref` (Sefaria range, e.g. `Genesis 6:9-6:22`), basis `triennial` / `selection` / `full` / `custom`, Hebcal snapshot (parashah, aliyot), set_by |
| `assignment_verse` | assignment, order, `verse_ref` (`Genesis 6:9`) — the key everything else hangs on |
| `source_default` | tenant, source key (Sefaria work, e.g. `Rashi on Genesis`; category), shown, order |
| `source_assignment` | student, verse_ref (null = all their verses), source key or exact Sefaria ref, assigned_by |
| `summary` | tenant, verse_ref, text, label, status `draft` / `approved` / `rejected`, drafted_via `mcp`, approved_by/at |
| `tutor_note` | student, verse_ref, author, body, timestamps |
| `translation_draft` | student, verse_ref, version (append-only), body, created_at |
| `recording` | tenant, verse_ref, uploader, kind `student` / `tutor`, Blob key, mime, ms, bytes, visibility `private` / `sent` (student) or `interim` (tutor's per-verse source), deleted_at |
| `text_cache` | verse_ref, language, version title, html, licence, fetched_at (global, not tenant) |
| `links_cache` | verse_ref, grouped related links, fetched_at (global) |
| `word` / `lemma` | per verse_ref and word index (counted as lib.js `verseWords` counts): morphology, lemma; lemma gloss and whole-Tanakh count (global) |
| `chant_render` | verse_ref, option id (`binder-avery`), table id, voice id, flags (`final`, `endOfAliyah`, `endOfBook`, `special`), render-key hash, Blob key `chant/<table-id>/<voice-id>/<hash20>.mp3`, ms, bytes, word timings, G1 and G2 results (global) |
| `chant_release` | option × voice × renderer version, review set, G3 result, passed_at |
| `g3_verdict` | release, render, pass/fail, reason codes (engine spec 7) |
| `play_count` | tenant, day, option, count (aggregate only, D8) |
| `audit_event` | tenant, actor, action, target, at |

- **Customs.** `tenant.customs` keeps the haftarah `customs/crc.json` shape (`calendar`, `haftarahRite`, `torah`, `nusach`, `versions`, `translations`, `divineName`, `entryCap`, `credits`, `toConfirm`). CRC's copy sets `nusach: "binder-avery"` (D6, ruling 14) and keeps `toConfirm: ["torah","entryCap","nusach"]` as MISSION says.
- **Texts.** Fetched from Sefaria per verse ref (Hebrew: "Miqra according to the Masorah"; English: JPS 2023 by its exact version title, plus the picker's editions, the `TRANSLATIONS` table in haftarah `scripts/translations.mjs`). Cached in `text_cache` with version title and licence. Never committed.
- **Verse key.** Sefaria refs (`Genesis 1:1`) everywhere, never week slugs or haftarah verse ids (`haftarah-54-3`, `torah-6-9`, which drop the book). The engine's `chant.json` design is keyed by week slug and verse id; here it becomes `chant_render` rows keyed by verse ref + option + voice + flags. The MP3 naming and render-key hash (integration spec 3.2) stay as designed, since they never contained the ref.
