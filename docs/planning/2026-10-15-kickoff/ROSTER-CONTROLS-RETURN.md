## Delivered behavior

- Three route wrappers: per-student `/workspace/admin/students/[studentId]/access`, `/workspace/admin/tutors` and `/workspace/admin/students/import`; narrow roster links and scoped incumbent-token CSS.
- Student access lists current tutor, guardian and student-identity links with effective access labels. Disabled students remain inspectable and allow cleanup, while tutor assignment and practice enabling are disabled. Explicit invitations remain the way to establish parent/student identities.
- Tutor assignment/removal, parent practice permission, guardian/student-link removal, cantor flag and ordinary parent/student/tutor role revocation each open an identity/consequence review. Link removal is explicitly limited to one student; ordinary grant revocation warns about congregation-wide effects. There is no admin-role picker or arbitrary account lookup.
- Every access confirmation re-reads the authoritative target projections, reconstructs the review and requires its exact identity/state fingerprint to match before POST. The server remains the authority and performs the published compare-and-swap checks. Current target grant/link revisions are used separately from student revision. Same-revision flag no-ops are accepted; ordinary revocation requires the next grant revision.
- CSV file/paste uses the exact supported five-column header, required parent email and optional student email. Browser checks UTF-8/file/request bounds; the server validates CSV syntax, rows and duplicates. File decoding preserves a BOM for authoritative rejection rather than correcting the header. No second CSV parser, invented fields or import/update/merge behavior is added.
- Server preview shows valid count, row-number issues and duplicates; explicit duplicate choice requires a new preview. Commit uses exact draft bytes, choice and opaque binding. The local five-minute deadline starts before the preview request. Editing, lifecycle revalidation or expiration invalidates the binding.
- Single synchronous latches prevent duplicate submission. Unknown outcomes never retry automatically. Successful writes followed by failed reads stay identified as saved. Unknown import keeps its exact draft read-only and keyboard focusable, while file replacement/duplicate choice/preview remain locked until explicit roster reload, inspection and acknowledgment; acknowledgment clears duplicate override and still requires a new preview. There is no receipt/idempotency endpoint to infer earlier failure.
- Private state stays in component memory. Registered same-session reloads await an in-flight mutation, then await fresh reads before provider reveal. Read generations, aborts and component lifetime checks reject replaced results; changed/failed session bindings discard the private subtree through the existing provider.

## Known contract limits

Relationship DTOs intentionally do not distinguish revoked grants from disabled/unverified underlying identities when effective access is false; the UI says “Access currently unavailable.” Revoking an already revoked role can therefore produce a server conflict. Tutor list pagination has no total/next cursor and a full last page may be followed by an empty page. CSV duplicate detection compares all five normalized fields, including existing disabled records; it cannot identify a specific uncertain prior request. Captures use synthetic names/emails and no licensed passage payloads. Live providers, full product completion and student release are outside this evidence.
