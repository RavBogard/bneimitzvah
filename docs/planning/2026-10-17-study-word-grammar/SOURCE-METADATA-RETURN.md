# Related source and edition metadata foundation

This checkpoint adds server-only related-citation and edition metadata parsers and a stateless Sefaria transport. It does not add a student interface, authenticated route, assignment storage, congregation defaults, rabbi approval or onsite source text. It preserves the separately verified6e150376 Word tools experience.

Related metadata must prove its connection to one canonical assigned-verse-shaped input using an exact anchor or a bounded complete vector of canonical anchors. Complex commentary citations remain inert strings; a complete provider work title is explicit rather than guessed from a citation. The copied, frozen output includes only identity, citation, category and short title labels. The future authenticated caller must establish the student's actual assignment; this pure module does not claim that authority.

Edition metadata retains exact version title, legacy language, nullable actual language and nullable inert license/source provenance. None establishes reproduction permission. Edition identity is the provider selector pair of version title and language. Root and the independent reviewer identified that including actual language in identity could produce two apparently selectable entries for one selector. The implementation now compares actual language as provenance inside that group; disagreement holds every row in the group in either order. Conflicting related IDs are likewise held as a whole. Every received row is counted as a projected entry, duplicate or held row.

Only fixed HTTPS metadata GETs are possible: related links explicitly disable text and sheets, and editions use the complete work title. No text endpoint, redirects, retries, cookies, credentials, remote destination from metadata or construction-time I/O. Each call has a10-second total deadline,5-second body-progress deadline,2MiB actual streamed-input and projected-output limits, row/field/expanded-anchor limits, fatal UTF8/JSON handling and bounded empty reads. Known text-body fields refuse the response. Aborted or late results cannot publish, cleanup cannot block the caller, and errors expose one fixed unavailable message. These are per-call bounds, not a process-wide concurrency or memory guarantee.
