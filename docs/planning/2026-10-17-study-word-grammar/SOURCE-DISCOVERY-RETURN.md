# Related citation discovery for an assigned verse

The new GET `/api/students/:id/study-sources` returns small citation pages for the actual selected verse in a student's current confirmed reading. It uses the unchanged StudyService and a real text page, preserving both original authorization passes. Callers cannot supply a source reference, work title, provider URL, category or edition. This is a backend endpoint, not a new student panel or source assignment feature.

The fixed metadata reader still disables source text and sheets. The service validates and copies its closed output for the exact captured verse, discarding unknown injected metadata without invoking or forwarding it. A public catalog hash detects changes; it grants no access and does not retain a historical catalog. Source errors, wrong-target catalogs, hash changes and dynamic page bounds remain enum-only outcomes until final authorization, so a concurrent denial or expiry wins.

Every accepted citation remains reachable through explicit ten-entry pages, including a4096-entry catalog and its final short page. Pages use deterministic ordinal provider-ID ordering. The documented SHA256 serialization includes all retained normalized entries and received/held/duplicate counts, so reordered provider rows are stable while changed off-page facts invalidate later pages. A hash mismatch returns409 before checking a shrunken catalog's page bounds. The complete private HTTP JSON body, including the authority envelope, is capped at64KiB; no silent truncation. Every response is private/no-store.

Root's integration review found that the first implementation reread a returned text-page object's target after awaiting metadata. The correction captures the primitive ref from the immutable authorized public request, checks the real page once and uses that captured ref throughout. Tests mutate the page in both directions: an original catalog remains bound to the original verse, and a wrong catalog cannot be rescued by a matching page mutation.
