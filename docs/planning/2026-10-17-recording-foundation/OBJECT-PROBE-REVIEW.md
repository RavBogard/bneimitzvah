## Design judgment

The bounded non-audio roundtrip is appropriate for the next synthetic milestone. It separately proves actual private object operations and transport observations without claiming delegated PUT/multipart/retirement, learner activation or erasure. Fixed project/store/Production/source/run, tiny fixed content, one nonoverwriting PUT, exact conditional DELETE, default silence, no static fallback and no replay after unknown outcomes preserve the existing boundaries.

Two items identified during the initial review, now resolved by root's design direction (implementation still pending):

1. **Reuse seam:** `scripts/private-media-oidc-probe.mjs` exports `runPrivateMediaOidcProbe`, while `identity`, `guardedEnvironment` and package-loading helpers are private. A new probe cannot directly reuse those private functions without an approved seam. The author should show exact pre/post public-probe composition or propose a minimal reviewed extraction. Do not duplicate full validators, spread/copy the complete hosted environment (which reads NODE_OPTIONS), weaken the native-profile conjunction or treat returned labels as authentication. Preserve every existing permission result/diagnostic contract and default no-import/no-network behavior. Any object operation must still receive only explicit OIDC/fixed-store options; post-I/O success requires the same fresh native token/profile and positive permission observation. Independently test that the hosted NODE_OPTIONS getter is never read, static fallback is removed and invalid/changed identity cannot reach an object operation or certify success.
2. **Read-condition proof:** positive Range206 with a matching If-Match does not distinguish honoring the condition from ignoring it. Add one same-object request with a deliberately mismatched bounded ETag; require the actual conditional-failure status (not generic network/auth/not-found failure), and accept no response bytes as content. This stays within the existing read-condition milestone. The positive request must independently verify exact Content-Range, total, byte count, MIME, ETag and fixed expected bytes. If provider behavior does not support the needed header, fail this proof rather than silently dropping the condition.

Initial review also requested explicit constants in the frozen implementation/test contract: exact payload bytes/length, range/denial-body limits, ETag length/syntax, GET-capability expiry, per-await and total deadlines, a finite operation/request ceiling and the closed result literal schema. These should be tight for a tiny marker; no user-configurable production expansion, repeated probes, multipart or automatic cleanup loop is warranted.

Root subsequently settled the narrow reuse seam: one fixed-Production read-only identity wrapper export reusing existing `identity()`, with optional expected-token equality; no arbitrary profile, duplicated predicate, SDK I/O or output in that wrapper. Actual metadata permission checks run before/after through a lazy flag facade that copies key names/getters rather than hosted values; enabled object mode rejects ambient metadata-probe flags. This is a defensible composition boundary, subject to source inspection and the NODE_OPTIONS/invalid-profile regressions above. Root also requires the wrong strong If-Match request to return 412 with no accepted media bytes.

Root fixed the ordinary engineering constants: 64-byte marker, bytes 0–15/64 positive range with exactly 16 successful body bytes, strong quoted printable-ASCII ETag at most 256 characters (no CR/LF or W/), error bodies at most 4096, 10 seconds per await, 5-second body idle timeout, 90-second total and at most 12 provider calls. One PUT and one conditional DELETE only. Any failure after PUT dispatch stops with requires-reconciliation and no automatic cleanup replay. Fixed result schema `private-media-object-roundtrip/v1` contains ok, literal phase, outcome passed|failed|requires-reconciliation, writeAttempted and checks{putVerified,rangeVerified,staleEtagDenied,unsignedDenied,deleted}; success requires all checks true. These resolutions close the initial concrete design issues. No additional design blocker is identified; final source must implement exactly this bounded contract and freeze any remaining short GET-capability lifetime constant.

### Trusted SDK control-response exception

Root's subsequent explicit exception is acceptable for this unwired tiny synthetic build: pinned SDK control operations retain fixed HTTPS endpoints, all override guards, explicit OIDC/store options, retries0 and 10-second AbortSignal/settlement deadlines. The SDK internally uses undici.fetch with redirects enabled and response.json without a byte cap or public fetch hook. No global Dispatcher replacement is required or authorized. The 12-call ceiling counts **application provider calls**, not redirect/protocol wire dispatches. Actual control JSON bytes, redirect count and memory use are not strictly bounded by this probe; timers cannot make synchronous JSON parsing preemptible. This is the same trusted-provider metadata boundary as the existing permission probe, not evidence that a malformed/unbounded control response is harmless.

Keep the exception confined to SDK control JSON, with no claim of redirect:error or strict response-byte limits for those calls. It does not authorize arbitrary returned hosts, secret/error reflection, broad credentials, a new endpoint override or static fallback. Raw signed object fetches (including denial/error bodies) still require exact origin, redirect:error, strict 16/4096 byte bounds, reader cancellation, body-idle/total fences and no later action after settlement/deadline. No provider-controlled content becomes a URL/path input without exact validation. This exception must not carry forward as an app media-byte transport allowance. Source review should verify the two boundaries separately rather than claiming offline tests can impose a nonexistent SDK transport hook.

## Cleanup and observation requirements

- After a positive PUT, provider path/type/ETag and authenticated exact bytes establish which object may be deleted. Conditional DELETE binds that original ETag. Never substitute a newer ETag following a mismatch or automatically rerun an uncertain PUT/DELETE. Root retains the opaque run/key for reconciliation; a failed check may leave this tiny non-audio object without implying a learner-audio retention mechanism.
- Metadata absence must use pinned SDK's recognized `BlobNotFoundError`/actual specific same-path not-found semantics after positively completed deletion. Generic errors, expired capabilities, empty/malformed results, authorization failures and timeouts are not absence. In-flight body readers must settle/cancel before the next mutation; cancellation never proves a remote accepted write was canceled.
- Unsigned denial requires a known-existing object, specific authorization status and positive authenticated observations on either side. A404 or failed read is not privacy proof. Direct reads require one exact private-store HTTPS origin derived from pinned SDK behavior, no credentials or redirects, bounded/discarded error bodies and cache bypass. Cache=0 is not signed, and a read capability is not Range-limited: server-only custody remains necessary. Do not claim old bytes/caches/backups are recalled.
- Every await needs a total deadline and post-await cancellation fence before starting the next action. A late PUT/read/delete completion after failure must not continue the sequence or emit success. Failure results contain only fixed labels/booleans; raw errors, URLs, bodies, token/delegation material, provider headers and environment values remain private. Read default-disabled behavior must be tested in a scrubbed child with import/network/credential tripwires.
