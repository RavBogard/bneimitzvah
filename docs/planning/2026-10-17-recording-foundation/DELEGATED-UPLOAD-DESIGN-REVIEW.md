# Delegated-upload proof — independent design review

Reviewed the bounded draft at sourcebc10207a38acfcf1bafc7e850b1fed1236989c13, pinned @vercel/blob2.8.2 and current primary documentation. Design review only: no code/tests, credentials, database/provider operation or private data. Root retains architecture and explicit operational release.

## Conclusion

The six cases are a reasonable minimum for testing this conditional permit→retirement premise. Single-PUT success is insufficient because the same delegated put capability reaches multipart. Published optimistic concurrency plus successful held-request observations is a defensible scoped premise for root to accept; it is not a proof of every provider execution or lifetime, permanent quiescence, physical erasure, part cleanup or a production cost cap. Missing remote/transport evidence must remain inconclusive, and real media/finalization/cleanup remains separately gated.

Acceptable for implementation AFTER the following narrow clarifications. No new provider, generic proof framework, receipt schema or extra product capability is needed.

## Necessary clarifications

1. **Prevent ETag ABA and false single-use proof.** Explicitly choose different deterministic P, accepted-upload and R bytes. Require observed post-upload ETag B!=A and retirement ETag !=A (also different from the replaced current value). Do not assume every successful overwrite changes an ETag. Initial P must be create-only at the exact key; never reset/recreate P or delete R, including after duplicate-build collision. A same-body P overwrite or later recreation can recreate the old ETag and make the old grant usable again. Existing duplicate-build exception must not authorize this reset. If initialization collides, stop for reconciliation rather than adopting/reinitializing it.

2. **Denial must test the intended cause.** Freeze a numeric grant lifetime covering the whole bounded round with margin (root could choose300s for180s total) and require sufficient unexpired delegation/URL time at initiation AND final response for cap/MIME/retirement observations. Expired signatures, malformed protocol, network errors, unrelated403 and wrong paths cannot stand in for provider size/type/conditional enforcement. Recognize the actual pinned provider failure class/code/status for the tested negative case; no raw messages. Test query expiry tampering separately as signed-input confinement. If the margin or causal evidence is lost, fail/inconclusive rather than renew/retry automatically.

3. **Keep the simulated client genuinely limited to the concrete URL.** Locally parse its delegation/signature/canonical query params to replay the pinned /mpu create/upload/complete protocol, with returned upload ID/key and part ETags only. Never pass the server-issued clientSigningToken, OIDC, static token, cookie, receipt handle or ambient SDK auth into that client. Use raw requests to avoid the SDK's pre-upload body-length rejection. Header override negatives must cover BOTH ordinary If-Match and SDK x-if-match, including current R replacing old A while signed query remains A, plus conflicting overwrite/suffix fields. No re-signing to make a tampered request. Require actual valid multipart reachability before interpreting cap or retirement failures.

## Source evidence and feasibility

[Signed-URL documentation](https://vercel.com/docs/vercel-blob/vercel-signed-urls) describes put as covering single PUT and multipart POST, MIME/byte restrictions in delegation and upload query options. [Conditional-write documentation](https://vercel.com/docs/vercel-blob#conditional-writes) states that intervening modification invalidates the prior ETag. Neither is a maximum in-flight lifetime or incomplete-part cleanup guarantee.

Installed `dist/chunk-XKVPKJPO.js` provides the precise local serialization evidence: buildPresignCanonicalQueryEntries includes MIME, byte cap, suffix, overwrite and ifMatch; presign signs the pathname/options/put operation. issueSignedToken sends path/operations/expiry/MIME/cap, not ifMatch/overwrite, so those latter restrictions belong in the concrete signed URL. No need to invent unsupported delegation fields. createPutHeaders uses x-if-match and x-allow-overwrite. Actual multipart requests POST /mpu?pathname=... with x-mpu-action create/upload/complete; parts include encoded key/upload ID/part number and completion uses JSON parts. addPresignedParams attaches the same delegation/signature/options, without requiring the signing secret. Respect multipart's JSON completion Content-Type rather than incorrectly sending audio/wav on that envelope; the final object MIME/constraints must remain bound by its original signed upload policy.

A6MiB nonfinal part and tiny final part fit the documented SDK minimum; three such uploads total about18MiB plus small tails/permits/retirements/negative bodies, fitting24MiB. Count every actually transmitted prefix/body, including partial failures; application-level100/180s caps still fail closed if exhausted. Held prefix tests must finish while the signed authority is still valid and prove R committed before the old request's completion. HTTP100 is remote header acknowledgment, not proof that backend condition evaluation occurred; TLS connected/flushed-only evidence must not be promoted to provider acceptance. No100/meaningful initiated-request evidence means the specified case stays inconclusive.

After successful multipart, verify bounded fresh private-origin bytes/hash/size and ETag against the exact generated concatenation, not size alone. For failed/retired multipart, retained R proves only current object state: incomplete uploaded parts can remain separately. Pinned public API inspection did not establish an abort/garbage-collection guarantee. Preserve only the necessary opaque MPU reconciliation identities in protected operational evidence if needed, never log them; do not claim automatic part erasure or broaden this checkpoint into cleanup machinery. This finite synthetic residue is a root operational consideration, not evidence that real-media cleanup is solved.

## Acceptance boundary

All current full native-context/late-guard/deadline/body-bound/static-fallback protections remain required. Successful origin observations bypass cache. Per-process limits do not bound duplicated hosted builds globally. Retiring to fixed non-audio R is a proposed irreversible access barrier conditional on provider enforcement, not universal physical deletion or proof of future audio storage safety. Any real cap/condition/multipart bypass blocks this premise and returns to root architecture. No independent implementation or provider acceptance is claimed by this note.
