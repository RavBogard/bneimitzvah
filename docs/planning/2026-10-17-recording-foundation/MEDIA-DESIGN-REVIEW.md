# Independent private-media contract review

Reviewed root's original `docs/superpowers/specs/2026-10-17-private-recording-media-design.md` and linked `2026-10-17-private-media-spend-notice.md`, plus the already packed official `@vercel/blob@2.8.2` JavaScript/types and current ledger authority/registrar source. Source review only: no provider access, private data, tests, installation or runtime edits.

**Updated outcome: both original required revisions are resolved in root's revised local contract.** The server-only signed-GET transport and post-I/O byte fence are accepted as source-design choices. This does not establish actual provider behavior or authorize spending. Provider and cost comparison remain pending Daniel; the earlier $25 proposal is superseded and unapproved.

## Original required revisions

1. **Redirect enforcement is not supplied by SDK `get()`.** In packed `package/dist/index.js:100–210`, `get()` calls imported `undici.fetch` with only method, headers and signal. It does not set `redirect`, so fetch follows redirects. `GetCommandOptions` exposes no redirect option; the returned object omits final URL/redirect information. Consequently an adapter using this method alone cannot prove the contract's “no provider redirects.” Choose a narrowly reviewed server transport/adapter that enforces redirect rejection, or explicitly revise that guarantee and its permitted destination/credential behavior. Do not merely inspect the initial stored path or successful normalized status. Add synthetic redirect/foreign-destination assertions and actual provider range proof before activation.

2. **Playback must fence authority after external I/O, before any byte disclosure.** The contract explicitly rechecks finalization after I/O, but playback currently says only that each request resolves under fresh authority. A prefetch authorization transaction can finish before an awaited provider read crosses context revocation, deletion, recording revision or anniversary. Explicitly require a bounded byte buffer of at most 1MiB, full range/ETag/type/length validation, then fresh exact-mode/context/student/recording state and retention verification before creating the HTTP response. Do not emit partial response bytes before that final decision. Use the existing authority machinery and preserve stale-context cancellation; no duplicate authority layer is needed. Test denied/changed authority while headers/body are held, including retention crossing, submitted-to-deleting and child switch.

## Accepted mechanics and implementation obligations

- **Receipt atomicity:** external verification outside long database locks followed by one authorized transaction consuming the exact receipt and registering/auditing the original immutable identity is correct. Existing `src/server/recordings/registration.ts` opens its own authority transaction and `data/recordings.ts` generates the ledger ID; those cannot simply be called as-is inside a separate receipt transaction. The stated narrow internal transaction/ID seam is necessary. Receipt/asset/recording unique bindings, current lease CAS, mismatch rejection and audit rollback must be demonstrated together, including a lost acknowledgement reconciled against the original receipt. No anonymous callback may register anything.
- **Write-only grant:** SDK `issueSignedToken` supports exact pathname, operations, validity, maximum size and content-type scope. Use only `operations:["put"]`; never expose `clientSigningToken` or an OIDC/static credential. `allowOverwrite` and `addRandomSuffix` are URL-signature options, not delegation-token options in 2.8.2; set both false on the presigned URL. Phrase “both delegation and URL” precisely for the constraints supported at both levels. Possession of the URL must not permit changing its signed path/options, reading, deleting or listing. Nonoverwriting the fixed path and pinning ETag across verification/retries avoid content replacement races; the live synthetic proof remains required.
- **Range transport:** SDK `get()` does accept server-constructed Range/If-Match through its low-level headers, but normalizes successful responses (including 206) to `statusCode:200`; `blob.size` reflects Content-Length, not the complete recording size. The specified exact Content-Range/ETag/type/actual-byte validation is therefore required. Use known ledger length for total/bounds and never forward arbitrary client headers or provider errors. Missing, ignored, malformed, oversized or shifted ranges must fail closed.
- **Child playback:** authenticated POST with the existing practice header followed by a bounded local Blob avoids native audio's header limitation and Function response size limits. Bound aggregate assembly to the verified whole-recording byte length, discard partial buffers, stop playback/revoke object URLs on lifecycle departure and denial, and keep bytes out of persistent storage. The already-declared playing recheck interval/hidden-tab behavior must be fixed and tested before wiring; previously delivered bytes cannot be remotely erased.
- **Cleanup:** independent worker authority, short CAS claims, old/new ceremony irreversibility and tombstones covering grant expiry plus in-flight late PUT are the right direction. A completed orphan delete must not release admission accounting or erase reconciliation state while the same grant can still materialize an object. Disabled user/membership/tenant cannot disable cleanup. The explicitly deferred worker-role/schema/endpoint/lease/backoff design must be reviewed and implemented before real upload activation, rather than leaving cleanup for an operational follow-up.
- **Admission and provider isolation:** pending captures, quarantined/retained bytes, grant reissue, actor/tenant rate limits and fixed deadlines need explicit values and atomic accounting before activation, as the contract already requires. The earlier $25 notice has been superseded without approval; no provider is selected by this review. Production-only credential/store binding and denied known-store Preview/Development probes remain actual acceptance gates; no new billing, licensing or UI gate is introduced by this review.

## Revised-contract confirmation

Re-read the exact root-owned managed media design after capture review. SDK 2.8.2 publicly exports `issueSignedToken` and `presignUrl`; its implementation permits scoped `get`/`head` operations and builds an exact-path private read URL. Keeping the signing pair/read URL server-only and using explicit fetch with `redirect:'error'`, omitted credentials and server-owned Range/If-Match removes the identified SDK-get redirect gap. Do not use SDK `get()` in this path. Public API inspection is offline source evidence, not a provider proof.

The revised contract now requires at most 1MiB buffered outside locks, then a new fresh exact actor/mode/context/recording-revision/state/retention authorization before releasing any response bytes. This resolves the second gap. Its at-most-30-second online playback lease is clipped to authority/retention expiry and measured conservatively from client request start; hidden/concealed lifecycle clears bytes. These are accepted design bounds, with timer/late-result/provider behavior still requiring the stated independent implementation evidence.

No schema or product implementation is approved by this review alone. Root may issue bounded receipt/storage-adapter and cleanup contracts with the stated invariants. Existing 0020 and the unwired PCM verifier remain unchanged. No store, provider call or new spending occurred.
