# Headless canonical capture

Bounded implementation on the accepted PCM verifier34443ff, alongside the separate operator76abf76. Only capture.ts, the public worklet, this note and recording-capture.test.ts are owned here. No UI, authority, runtime, schema, storage, provider or policy wiring changed.

`createRecordingCapture({signal})` creates one take with explicit `start`, `stop`, `dispose` and state inspection. Import/factory creation requests no permission. Start requests mono microphone input and an actual24000Hz AudioContext; another actual rate fails unsupported rather than claiming resampling. The worklet downmixes finite samples to signed little-endian PCM16, transfers <=4096-frame buffers, and fills every output channel with silence. Main and worklet both enforce frame/byte caps; the main also stops at ten minutes. Version1 ready/PCM/stop/done messages have closed fields, contiguous sequence and matching final totals. An explicit stop flushes the bounded tail then produces a local canonical44-byte WAV Blob, with client-derived byte/frame/duration facts. These facts are not trusted server registration proof.

Abort, disposal, hidden-document notification, ended tracks, interrupted context, malformed worklet messages, setup failure and deadlines clear PCM references, stop all tracks, disconnect nodes/port and close the context. Late permission resolution stops its tracks and cannot restore a take. Setup after permission is bounded10s, stop acknowledgement500ms and close acknowledgement1000ms; a stalled close cannot yield success. No upload, object URL, browser persistence or automatic submit exists. Future workspace ownership must call abort/dispose on unmount or rightful-context changes. There is no workspace integration in this slice.
