These entries are student-scoped human records, independent of Torah/haftarah assignment identity, recordings and practice-event history. ## Accepted root mechanics

- **Identity/lifetime:** namespace the client UUID by `(tenantId, studentId, entryId)`, with tenant-qualified student/creator FKs. No assignment/verse FK or revision dependency. Creator membership and user identity are immutable. Do not transfer ownership on an admin edit or depend on a former creator grant remaining active merely to read the historical entry.
- **Authority:** tutor/admin can create under the existing staff note-write gate. A current authorized tutor can edit/delete only their own original membership's entries; a current authorized admin can edit/delete any entry for that student. Other assigned tutors, students, parents and explicitly selected child practice read only. Ownership is an additional check after live capability authorization, never a substitute for it. Overlapping parent/tutor modes remain explicit; base modes must not silently consume a practice handle.
- **CAS/tombstones:** one current head, positive version, no full-text history. Edit/delete must match current version under an entry lock. Deletion atomically clears summary, increments version and irreversibly tombstones the entry. Retain identity/version; no restore, stale-delete success or delete/recreate ABA. All normal reads/lists exclude tombstones; mutations cannot revive them even with the current tombstone version.
- **Create replay:** only the same creator membership+user, exact normalized lessonDate/summary, live undeleted **version 1**, and fresh current authority may replay the same scoped UUID. An edited or deleted entry conflicts even if text later cycles back. An admin's broad edit privilege does not let that admin claim another creator's create replay. Unique-key contention must re-read/lock the winner and repeat these checks; no stale-create success or text receipt/history mechanism is added.
- **Input:** closed date/text/version/entry-ID contracts; strict real date-only value and bounded nonblank plain summary of at most 4,096 UTF-8 bytes, CRLF normalized to LF. Validate Unicode/control bounds consistently with existing plain-text work. No time, duration, hours, scheduling, actor, email, client timestamp, HTML interpretation or extra fields. Root chose no arbitrary future-date rule: lessonDate is human classification, not a scheduling mechanism.
- **View:** lesson-specific safe server-derived displayName plus entry ID, lessonDate, summary, version and live `canEdit`/`canDelete`. No raw author/user/membership/grant IDs, emails, handles or timestamps. Email-like, control-bearing, oversized, blank or otherwise unsafe names receive a generic label. Immutable creator identity stays internal; current safe name lookup does not change ownership. Permission booleans follow current selected mode/capability/creator membership and are never trusted on writes.
- **Listing:** bounded keyset order `(lessonDate DESC, entryId DESC)`, scoped to the currently authorized tenant/student and excluding deleted entries in every projection. Date edits during pagination require refresh; no cross-request snapshot guarantee or activity-event feed is claimed. Cursor selectors grant no authority.
- **Security/audit:** retain authority and entry locks through writes/replay waits; recheck real session/context expiry after waits and before success, no-op, conflict or replay returns. Security audit contains server-derived actor/action/entry identity only, never summary text. Additive schema uses FORCE RLS, matching tenant USING/WITH CHECK, minimal grants, immutable creator/key and monotonic versions; no new grant path.

Former teachers' revoked grants must neither erase lesson visibility for still-authorized families/staff nor allow the former teacher to read/edit after access ends.
