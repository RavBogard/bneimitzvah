Issue the grant only **after explicit local stop/save**, so a ten-minute take cannot exhaust a five-minute grant before upload starts. Use existing app transport with exact selected mode/student and X-Practice-Context where required; the SDK browser helper must not hide this header. A durable receipt binds original request/recording/asset IDs, actor/authority/context, student/tenant, opaque pathname, fixed expiry/caps and state. After receipt creation, issue a five-minute **write-only**, exact-path, nonoverwriting, audio/wav-only, capped PUT grant using server `issueSignedToken` plus `presignUrl`, with constraints in both delegation and URL options. Freshly recheck authority after awaited provider work before returning it. The intentional browser-visible exception is this short-lived write capability; it supplies no read/list/delete/overwrite permission and no store/OIDC/static credential. Upload uses direct fetch with credentials omit, redirect error and no-referrer; no app cookie or practice header goes to storage. A client-reported PUT result supplies no trust.

No anonymous upload-completed endpoint is needed. Explicit user finalization is the authoritative path; provider callbacks cannot register a student recording. Repeated begin/finalize requests keep the original immutable capture identity, cannot retarget it across contexts/actors, and do not mint unbounded replacement grants or reset deadlines.

## Verification and atomic registration

Quarantine is an application state: bytes are in a private store but have no authorized playable recording. Verify the immutable server-owned object under bounded abort/deadline and size limits using the accepted canonical PCM verifier. MIME, duration, size, hash and provider URL submitted by the browser are never proof. Object ETag/byte size/path and server-computed SHA/frame facts remain internal.

Do external byte I/O outside long-held database authority locks. Then use a fresh authorized transaction for the same receipt, current actor/context/student/retention and exact lease revision. Consume the receipt and register the original recording ID/asset in **one transaction**, including audit. Refactor only the narrow internal registrar seam necessary for this atomicity; never register first and consume a receipt later. A revoked/expired/changed context at finalization leaves unplayable quarantine for cleanup. A retry must prove the same original capture/bytes and current authority; it cannot replace content, revive deletion, silently adopt a different context or duplicate audit. Save failure/unknown outcomes require receipt reconciliation, not a new upload by default.

The new migration adds canonical audio/wav support without pretending legacy WebM/MP4 declarations are decoded; the new upload path accepts only the verified canonical format. Existing ledger list/submit/remove capabilities and all-state retention remain unchanged.

## Online playback transport

Native audio src cannot send the existing X-Practice-Context header. Do not expose signed provider GET URLs as a workaround. The client uses the existing authenticated transport to POST closed byte-range requests for one recording ID/revision, at most1MiB per response, then constructs a private local Blob/object URL for native controls. This avoids relying on >4.5MB Function responses and retains exact child headers. Abort/discard all partial bytes on context/session/assignment departure or denial; never store them durably in this online slice.

Every chunk request resolves the recording under fresh exact-mode authority and current retention/state. Parent dashboard is denied; staff reads submitted only; deletion/revocation must fail later chunks. Use SDK issueSignedToken/presignUrl for a **server-only**, exact-asset, short-lived GET capability, then our explicit fetch with redirect error, credentials omit and server-constructed Range/If-Match. SDK2.8.2 get() follows redirects and cannot establish this no-redirect contract; do not use it here. Signed read URLs never enter DTOs, logs, callbacks or browser state. Require status206, exact Content-Range total/start/end, expected ETag/content type, actual bounded byte count and cancellation; ignored/wrong ranges fail closed. Never forward arbitrary client headers, object URLs, raw SDK results or errors. Private no-store/no-referrer/nosniff responses, no provider redirects or static cache. Live synthetic proof must verify provider range behavior before activation.

Buffer at most1MiB outside database locks, then perform a NEW fresh exact actor/mode/context/recording-revision/state/retention authorization after provider/header/body I/O, before constructing/releasing the byte response. Do not stream partial bytes before that last fence. Rejection aborts/cancels and discards the buffer. User authorization before an external wait does not establish authorization after it. Quarantine verification uses the same redirect-rejecting server transport with its separate bounded verifier stream and remains unplayable until fresh atomic registration.

Local native playback uses preservesPitch for supported speed controls. Workspace lifecycle stops playback and revokes object URLs immediately on local scope changes or concealed/hidden state. Online playback authorization is at most30seconds, clipped by current session/context/recording-retention expiry. A closed authorize-playback operation returns only the bound recording ID/revision and positive remaining lease milliseconds <=30000; it issues no bearer read permission. Measure client expiry conservatively from the monotonic request-start time, so network delay cannot extend it. Recheck before expiry while playing; failed/expired/mismatched/stale acknowledgements stop/clear rather than extend it. Every later byte request still requires full authority. A known denial stops/clears immediately. Do not promise instant remote revocation of bytes already delivered. Client timer/lifecycle behavior needs independent runtime review before wiring. This online contract does not authorize offline caching; future PWA/offline leases are separate.

## Physical deletion and reconciliation

An account-independent maintenance principal, separate from the runtime user role, stages all overdue private/submitted rows and deletes explicit-deleting assets and expired/unregistered quarantine. Disabling a user, membership or congregation must not stop retention cleanup. Use a narrowly granted worker DB role, Production-only credential and authenticated canonical-host scheduled endpoint; runtime credentials cannot claim physical completion. No owner DB URL in application runtime, no SECURITY DEFINER shortcut without independent approval.

Use short durable claim leases/CAS around provider I/O; do not hold SQL locks during storage calls. Record deletion confirmation only after provider confirms absence, and keep opaque object tombstones/reconciliation sufficient to catch late writes after grant expiry. A single orphan delete is not proof no in-flight PUT can later materialize. Handle duplicate jobs, vanished objects, provider timeouts/unknown outcomes, retry backoff and process interruption without making audio playable. Job results expose aggregate counts only. Hourly bounded batches are proposed; due metadata access is already denied at the exact anniversary, and physical cleanup latency must be documented/tested rather than claimed instantaneous. Worker authority, tombstones/schema/grants and the chosen retry bounds require separate independent design review before implementation.
