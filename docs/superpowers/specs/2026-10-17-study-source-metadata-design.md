## This slice

Add server-only pure closed parsers and a stateless fixed-host transport for Sefaria related-link metadata and version metadata. No global cache/coalescer, runtime/HTTP composition, database/migration, authorization refactor, package, provider permission or paid service. Existing Bible chapter transport/parser and public coalescer remain unchanged: chapter parsing and its512KiB cap are unsuitable for related metadata, and the coalescer is not a hard bound on physically unsettled canceled work.

Related requests accept exactly one valid canonical Tanakh verse, using existing catalog validation. Fetch only fixed HTTPS `www.sefaria.org/api/links/{encoded-ref}?with_text=0&with_sheet_links=0`. Version requests accept a bounded plain complete-work title and fetch only fixed `/api/texts/versions/{encoded-title}`. This trusted internal input must later come from candidate-proved provider `index_title`; string validation alone does not establish recognition. Never guess it by splitting a source reference or invent a Bible-only commentary registry. No text endpoint, remote URL from data, credentials, cookies, redirects, fallback host or retry. A trusted fetch injection supports offline tests without environment switches; callers cannot configure an origin/path or provider headers.

Bound each request by an absolute10-second deadline,5-second body-progress timeout,2MiB streamed input,4096 related rows or512 edition rows, bounded consecutive empty reads and fatal UTF8/JSON validation. These are per-call data/time bounds, not a process-memory/concurrency guarantee. Enforce optional advertised byte bounds and actual bytes; oversized/invalid responses fail closed without truncating a catalog. Abort/refusal/timeout cancels or aborts work, fences late completion and returns a fixed unavailable error without body, URL, cause or upstream exception. Do not await a hostile never-settling cleanup in the caller path.

Project only safe small metadata, copied/frozen. Related candidates need provider link ID, source ref, complete index/work title, category, short optional English/Hebrew title labels and evidence binding the connection to the requested canonical verse. Exact anchor ref or a validated bounded expanded-anchor vector must prove that binding. Never derive a work title by splitting a complex source ref, or infer approval from category. Complex source refs are bounded plain citation strings, not Bible chapter references or fetch destinations. Reject HTML/control/bidi/invalid Unicode; normalize metadata to NFC. Ignore unrelated metadata fields instead of guessing their types. Known nonempty text-body fields hold the response; nested title-language labels are metadata, not proof of verse content.

Return a closed catalog with the requested verse/work identity, immutable projected entries, held-entry and duplicate counts. Malformed/unbound entries are held with counts, never silently repaired. Deduplicate exact projected repeats; conflicting rows with one provider identity are held, not resolved by first match. Bound each projected field and aggregate result. No arbitrary provider URLs become active links. Versions expose only exact version title/language and bounded nullable license/source metadata; a source string remains inert provenance. Unknown/missing licensing is explicit metadata, not permission. Version selectors are not immutable content identities. Never include notes, HTML, source bodies, purchase URLs, pronunciation, actor/session/database fields or whole arbitrary provider records.

Approved field bounds are UTF8 bytes: opaque ASCII link identity1..128, source ref/work title512, category128, optional short title labels256, version title512, language64, license256 and inert source2048. Projected catalogs are at most2MiB. Preserve provider `language` and nullable `actualLanguage` separately: legacy orientation does not establish an edition's actual language. Count every received row exactly once as an entry, duplicate or held row. A malformed/conflicting row with an identifiable shared provider identity holds that entire group, including earlier duplicate rows; order cannot choose a winner. Bound expanded-anchor vectors independently and within the total input limit.

Edition identity is the provider selector pair `(versionTitle, language)`. `actualLanguage` is observed provenance in the compared projected value, not an independently selectable identity. Different actual-language values for one selector hold the entire group rather than producing two editions.

## Evidence and next boundary

Official contracts: [Links](https://developers.sefaria.org/reference/get-links), [Versions](https://developers.sefaria.org/reference/get-versions), [selected text v3](https://developers.sefaria.org/reference/get-v3-texts), [data-use guidance](https://developers.sefaria.org/docs/usage-of-our-name-and-logo). Two bounded metadata-only preparation GETs used no credentials or retained bodies: related links returned1,078,623 bytes/1828 rows; versions returned12,220 bytes/15 rows. The links probe's conservative recursive language-label detector held its body, which is not evidence that verse content was returned. Versions had15 string title/language/license fields and14 string source fields plus one null. Boolean-looking unrelated fields sometimes are strings; discard them. These observations are schema preparation, not permission or live availability guarantees.

Later authenticated discovery must verify actual assignment/verse and both authority passes around public work. Later assignment storage needs transactional revision/idempotency/audit and independently reviewed tenancy. Existing ordinary-admin `manage-defaults` is insufficient for rabbi-only defaults/summary approval; use an explicit protected clergy capability before claiming that gate. No such authority is granted or simulated here. Selected onsite text additionally needs an exact edition, rights/provenance policy, identity/content checks and a separate safe-content contract. Keep unknown rights held.
