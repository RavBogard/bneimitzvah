## Candidate permit and retirement mechanism

Root chooses a candidate protocol for TESTING ONLY: create a unique server-owned non-audio permit P, capture its strong ETag A, and disclose only an exact-path short-lived PUT URL signed with ifMatch=A, allowOverwrite=true, addRandomSuffix=false and matching MIME/size restrictions in BOTH delegation and URL. Signing material and OIDC remain internal. This is a deliberate conditional-overwrite alternative to the earlier nonoverwriting paragraph in the high-level media spec; that app paragraph is not silently activated or amended by a probe.

One successful upload changes A and prevents replay. Trusted retirement conditionally replaces the current object with DIFFERENT fixed non-audio bytes R, confirms R through a fresh private-origin read, and retains R at the same key. Never DELETE the retirement barrier in this checkpoint. Old A-bound writes must fail after R even if they began before retirement. A retirement marker is not a recording and does not reserve the original full audio byte budget forever. Actual receipt/worker accounting and compaction remain future reviewed contracts.

**Independent design corrections accepted:** P, accepted test payload U and R are three distinct deterministic bodies; require observed successful payload ETag B!=A and retired ETag!=A. Create P ONLY with nonoverwriting create semantics, never reset/recreate P/A at the same key, including duplicate builds. This prevents the probe itself from creating an ABA/reset path. Strong provider ETag/OCC semantics are a stated provider trust premise, not a substitute for the future canonical byte verifier/SHA.

Freeze delegation and concrete URL expiry to round-start wall clock+300000ms, with the180000ms monotonic round ceiling. Every cap/MIME/condition/retirement negative requires an explicit >=60000ms unexpired margin when its final response is classified; otherwise it is inconclusive, not evidence for that restriction. Recognize the relevant fixed HTTP/provider outcome (for example conditional precondition failure) and never mislabel unrelated authentication/expiry/network failure as enforcement. Intentional signed-expiry tamper remains a distinct confinement case.

## Six fixed synthetic cases

Use one opaque run ID and at most six fixed child keys under acceptance/<run>/upload-proof/. Permit and retirement bodies are distinct deterministic64-byte non-audio markers. The audio/wav MIME label tests upload policy only; generated bytes are deliberately not valid/playable WAV and never become a registered recording.

1. **Single PUT and replay:** raw fetch using only the concrete URL succeeds at the64-byte cap, exact path/private origin and expected ETag/size. Old A replay fails and cannot change the new object. No client signing/delegation secret, OIDC, cookie or app context header is sent.
2. **Confinement and enforcement:** under a fresh matching A, raw cap+1, wrong/missing MIME, changed path/signature/expiry/conditional/overwrite query, duplicate critical query and conflicting condition headers must not widen authority or modify P. GET/HEAD/DELETE/list attempts using only disclosed URL material must not supply those capabilities. Verify P unchanged with trusted current observations after rejected mutation attempts; a stale-A failure alone is not a size/type test.
3. **Held single PUT retirement:** initiate a real TLS request, transmit a positive body prefix and hold the rest while trusted R commits; then finish the original request. Require refusal and current R bytes/ETag. Prefer explicit HTTP100-continue acknowledgement as evidence of accepted headers; record precisely whether evidence is remote acknowledgement or only connected/flushed transport. Delaying before request transmission is not this case. If accepted-request evidence cannot be established, report the case inconclusive for root review rather than inventing it.
4. **Valid multipart:** exercise the REAL pinned SDK-derived create/part/complete protocol using only the existing signed PUT payload, no OIDC/static/signing material. A6MiB first part and16-byte final part must produce the declared6MiB+16-byte object under that cap, then retire it to R. A wrong endpoint/malformed-part denial cannot stand in for capability isolation.
5. **Multipart total cap:** same effective delegated cap, valid first6MiB part and32-byte final part must not produce an over-cap object. Rejecting the oversize part or completion is acceptable only when authentic protocol reachability was established in case4 and trusted P remains unchanged. MIME/condition restrictions cannot disappear at completion.
6. **Multipart retirement:** prepare valid parts, hold a genuinely initiated partial completion request while R commits, then finish it. Stale signed A must not replace R. Include the critical attempt to replace A using condition headers while leaving the signature unchanged. No broadly rescoping/re-signing material reaches this simulated client.

Derive real multipart create/part/complete requests from pinned SDK serialization, replaying ONLY the original concrete signed payload at the fixed /mpu endpoint. Completion's application/json transport MIME is distinct from object MIME carried in x-content-type. Preserve the signed conditional query across ALL actions even where public multipart helpers omit a condition header. Override cases explicitly include HTTP If-Match, SDK x-if-match and conflicting overwrite headers. SDK high-level prechecks or ambient authorization cannot supply the tested client's protection.

If multipart is demonstrably unavailable using the concrete disclosed payload despite the correct protocol, record that narrower actual finding and obtain root approval instead of pretending cases4–6 passed. Effective unrestricted multipart, cap/condition bypass or overwrite after R is a provider/transport blocker. No real media activation or provider switch follows automatically.

## Resource, execution and output contract

New default-silent script/prebuild composition, exact opt-in flags, existing full native Production context/environment guard, actual provider OIDC permission and fixed store; no static fallback or app runtime surface. Reuse existing guarded identity and bounded transport mechanisms rather than creating a generic probe framework. The separately reviewed root-only operator pins the exact CI-passed source and one run; a staged Production build never becomes the normal canonical deployment.

Per process: at most six keys, total outgoing synthetic body bytes <=24MiB, at most100 application-level provider calls, total<=180s, per-await<=10s, byte-progress idle<=5s and existing monotonic post-settlement deadline fences. Raw response bodies have explicit small/error or exact expected bounds, redirect:error, credentials:omit, fixed origin/path and cancellation/discard. Held requests are explicitly tracked/settled; no later action or success after deadline/context failure. No automatic retries, automatic replay/cleanup after unknown writes or raw provider diagnostics. Preserve exact reconstructible keys and journal for root reconciliation.

The already accepted pinned-SDK CONTROL-plane JSON trust exception remains limited to this synthetic provider observation. It is not an app byte transport exemption. CLI internal duplicate-build risk is accepted here only for this bounded generated non-audio suite, with per-process rather than global bounds and strict duplicate/unknown reconciliation. It is not accepted for real media. Successful final markers are deliberately retained; report finite observations rather than quiescence or erasure.

Unfinished multipart parts are distinct from the final key and its R marker. No supported abort/list-parts operation or provider garbage-collection deadline has been established in this bounded review. A successful conditional final-object test cannot claim those parts were deleted, cannot release their real-media retention obligations and cannot by itself approve the delegated path. Finite synthetic leftovers require protected root reconciliation; do not invent a cleanup framework or assume S3 lifecycle settings that this store does not expose.

Closed output contains a fixed schema/version, run-independent booleans for the six cases, literal phase/outcome, whether any write was attempted and whether reconciliation is required. No URLs, keys, ETags, headers, tokens, byte bodies, IDs or arbitrary errors. Partial/inconclusive cases cannot be success. Author and independent mocked tests must show actual pinned protocol serialization, control/byte bounds, stale conditions, deadline/late-environment changes, held-request ordering and fail-closed unknown outcomes. Then normal composed tests/Windows+Linux exact CI, independent operator review and root's explicit synthetic native run. Passing this accepts only the provider capability/barrier premise; real receipt/finalization/cleanup still requires its own reviewed implementation.
