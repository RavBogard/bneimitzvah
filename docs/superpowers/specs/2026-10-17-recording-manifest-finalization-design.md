## Incorporated independent design precisions

- Durable consumption matrix: receiving/verifying are unconsumed; registered requires complete reciprocal consumption; retiring/terminal can be unconsumed OR irreversibly consumed. Once set, link IDs and verified canonical facts never clear/change. SQL deferred checks on BOTH sides inspect the final complete nonempty slot set with exact index/count/length sum and explicit NULL refusal. Immutable seal tuples are separate from current lifecycle/claim/date revisions: those invalidate tickets without invalidating already consumed content.
- Every new physical-release/retirement-confirmed fact starts NOT NULL/default false, and INSERT-time triggers reject forged initial true facts. Existing table-wide runtime INSERT grants make UPDATE-column restriction alone insufficient. Only the independently scoped trusted maintenance adapter may transition false->true after complete evidence; actual production worker login/scheduler remains absent. No runtime INSERT/UPDATE/SET ROLE/GUC spoof can manufacture release or terminal R evidence. Never grant generic runtime DELETE.
- One primary accounting predicate proves reciprocal exact consumption. Audio = unconsumed unreleased receipt-slot bytes + ALL ledger bytes except SQL-proven consumed-linked ledgers with valid worker capacity release. Takes = unconsumed unreleased receipt takes + ALL ledger takes except the same physically released linked ledgers. A SQL-proven consumed receipt contributes neither audio nor take reservation, independently of its physical-release bits. Unlinked/deleting legacy rows are always charged. IDs remain the distinct permanent union, markers64/slot remain separate. Both receipt and ledger aggregate branches use the SAME exact link predicate under admission; no asymmetric exclusion.
- SQL enforces nonNULL initialization and monotone dispatch/attempt/fault history. A replacement claim/session/date/retiring transition cannot clear unresolved possibly dispatched audio history; only exact positive reconciliation/terminal evidence resolves it. Fault-hold evaluation samples database actual time AFTER admission waits, handles unknown/legacy NULL conservatively, and never blocks cleanup itself. Claim expiry is not permission to retry U. Cleanup may continue despite exhausted foreground budgets, through its own persisted finite claim/observation/known-conflict budgets and backoff; unknown R never automatically authorizes another replacement. One known-conflict U-won branch may verify exact B then conditionally R(B), as already accepted; all other ambiguity reconciles before further mutation.
- Mint a private one-use verifier ticket only after known EOF/hash/frame verification and fresh original authority. Bind exact receipt/original ID/asset/store, immutable ordered seal tuples, original authority snapshot, claim operation/attempt/deadline and canonical facts. Consume its identity synchronously BEFORE the first await in finalization. A failed/unknown finalization never reuses it: reconcile the same durable identity/link, or spend a separately budgeted new whole verification. Exact consumed replay is a distinct freshly authorized read/settlement branch returning after acknowledged outer completion and final freshness, with no additional audit/charge. Partial/unrelated/deleting/ineligible replay refuses.
- Linked deletion stages head/slots in an EXPLICIT existing service transaction step after its actual ledger lock/update; a deferred consistency constraint validates deleting/retiring linkage at final commit. NO immediate per-ledger head-staging trigger may run inside0020's multi-ledger date phase. Date finishes ALL old ledger updates before ANY head/slot staging, without admission. A native multi-ledger barrier must prove an earlier head remains unlocked while date waits on a later ledger. Persisted WAV projection gets its own closed linked-canonical validator in existing page/submit/delete paths; keep legacy registrar input compressed-only. Merely widening shared descriptor validation is insufficient.
- Terminal retirement distinguishes known R(A) with unknown B from the U-won verified-B branch: require exact verified R marker/hash, R tag != A and != any KNOWN B, without fabricating B or permitting a NULL comparison escape. Proven never-opened remains the distinct possible-P-marker class. Complete terminal evidence and release constraints require ALL expected slots, not vacuous NOT EXISTS checks. Worker provenance is explicit maintenance metadata; do not invent a human actor/audit for its observations.
- The two-buffer limit covers orchestrator-held/prefetched full chunks, not a fictitious process-wide2MiB allocation cap: C has separately bounded response/copy temporaries. Sequential reads or one prefetch suffice. A head verification claim uses ONE unit of the same foreground claim pool as slot claims; count all eligible kinds together for student/actor/tenant ceilings. This eligibility pool is not physical cancellation/concurrency or a billing guarantee.
- Closed fixed-key P/R observation methods may be factored within the private C engine where same-key reconciliation needs them, with exact marker31/33/header/hash/context/deadline checks. No arbitrary key/path/token/body/URL/namespace override or general reader is added. Preserve all four C repaired regressions, actual SDK wire-mapping tests and normal recording namespace.
