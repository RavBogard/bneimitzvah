## Bounded architecture decision

Add only a server-internal authorized transaction composition seam for an already independently verified descriptor and an original recording ID. This is useful before durable receipts exist: future receipt consumption, ledger registration and create audit can share ONE authorized transaction. Do not add receipt tables, WAV acceptance/migration, provider operations, upload/playback routes, runtime composition, UI or cleanup workers here. Existing0020, policy formats, public DTOs and lifecycle/retention remain unchanged. Root accepts the existing source inventory and independent design input; these mechanisms are root decisions, not new Daniel rulings.

Keep the existing registrar's register(request,selection,descriptor) behavior, including random new recording IDs and exact-descriptor asset-based retries in private/submitted state without duplicate audit. Extract the smallest shared insertion/audit core; do not make legacy asset replay require a newly generated matching ID.

Expose one internal authorized callback method (for example withRegistrationAuthority). It enters the EXISTING createRecordingAuthority write=true/allowDue=false once and gives trusted server code the real same transaction, actor/student/freshness and a closure-bound registerVerified(originalRecordingId,descriptor). This is not an API accepting arbitrary caller-supplied authorization or a second/nested transaction. Verify external bytes before entering this callback; no provider I/O belongs under its SQL locks. The existing authority's final freshness check must run after the WHOLE caller callback.

## Exact original identity and atomic failure

Validate the original ID with the existing lowercase UUID validator and descriptor with the existing closed validator. Insert exactly that ID, current tenant/student, immutable asset/hash/media/bytes/duration, private1 and trusted current creation time. A conflict may query/lock ONLY the authorized scoped original-ID row; accept replay only when its asset and every immutable descriptor fact match and it is private/submitted. Return its current ID/state/revision, with no new create audit. Same asset/different original ID, same ID/different asset or facts, inaccessible foreign collision, missing scoped row or deleting state is generic conflict; never adopt another ID, change identity or revive deletion. No cross-tenant conflict diagnosis, upsert or delete/reinsert. Existing unique constraints suffice.

The new callback registration operation MUST throw on collision/invalidity/freshness/audit failure so earlier caller writes roll back. A caught registration failure must still poison this composition and make its outer callback reject, rather than allowing partial receipt-like work to commit. Use a small internal error/closed code; do not expose SQL/provider details. Legacy register keeps its existing generic conflict return by translating only its appropriate conflict outside the transaction/core.

**Independent design correction accepted:** existing identity handling masks ordinary errors to503 and preserves AccessDenied. Do not broaden that auth sanitizer. A private per-operation AccessDenied-compatible conflict signal may cross that existing boundary; recognize only its exact private identity outside the authorized transaction and translate to the legacy conflict return, or a small exported internal registration-conflict error for the new callback caller. Ordinary401/403/404, database/audit failures and arbitrary callback errors must never become collision results. The private signal is transaction control, not a new HTTP authorization rule, and no route is wired in this checkpoint.

Closure lifetime is bounded to this authorized callback. Reject use after callback settlement. At most one registration invocation per callback is sufficient for one capture; reject concurrent/repeated use, and reject successful callback return with an unawaited registration still pending. Failure poisons the scope even when caught by trusted callback code. Recheck active/freshness before and after each awaited domain insert/conflict lock/audit, and call fresh after caller work. These fences prevent a retained closure from issuing later SQL or reporting a successful transaction after its authority scope ended; they do not make TypeScript descriptor types into byte or ownership proofs.

When caller work settles with registration pending, synchronously close/poison the scope, then observe/drain its tracked operation INSIDE the same transaction before rejecting and leaving it. Never race connection release/rollback against queued registration SQL. Closed continuations must issue no next SQL after any await. Apply the existing database failure/timeout behavior; draining is not a claim that cancellation physically retracts an accepted command. Callback errors likewise close and drain before transaction exit. Independent review must exercise this ordering, not only promise rejection.

## Acceptance and checkpoint

Author and independent reviewer own separate tests. Demonstrate exact original ID/new private row/single audit; exact private/submitted retry/no duplicate audit; ID/asset/facts/foreign collision/deleting rejection; legacy asset retry unchanged; caller write plus ledger/audit atomic rollback on conflict (including caught conflict), callback failure, audit failure and expiry/anniversary crossing after awaited work; escaped/repeated/concurrent/unawaited closure refusal. Use synthetic caller writes or existing audit fixtures, not a premature receipt schema. Native restricted PostgreSQL cases must exercise meaningful actual uniqueness/audit or authority waits for the new semantics; reuse unchanged authorization evidence rather than reproducing the full suite in another file. No arbitrary sleeps as proof of blocking.

Keep registrar absent from runtime/HTTP and preserve existing guards. Focused app/native checks and typecheck during edits, then required composed Windows/Linux/hosted checks before any release. Save one bounded source/review/return checkpoint. Native upload/multipart/retirement proof and later additive WAV/receipt/worker contracts remain separate. This slice alone is not a recording-save feature.
