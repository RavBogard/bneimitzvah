## Evidence and selected change

The original single-write round remains failed at verify; preserve its journal, keys and artifact. The separately accepted read-only round observed the complete known upload body, with Content-Encoding present, Content-Length absent and a GET ETag different from HEAD. These are current facts, not the original B or historical headers. HTTP allows content-negotiated representations to have different strong tags ([RFC9110 section8.8.3.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8.3.3)); requesting identity is an explicit representation preference ([section12.5.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.3)), not proof the server honors it.

Root selects ONE separately versioned derivative: mode `single-write-identity-v2`, schema `private-media-single-write-identity/v2`, same three existing SINGLE_WRITE flags and fixed store. Add a separate exported runner/constant in the existing script. Preserve the original writer, original selection and read runner/selection byte exactly. Only CLI dispatch gains the exact new mode. No dependency, package, runtime route, storage schema or legacy operator change.

The new runner validates exact flags/mode/store/canonical UUID and mixed legacy-probe rejection before identity/SDK/fetch work. All flags absent remains silent. A direct call with another mode must fail without dispatch. A lazy live environment facade translates ONLY the validated mode to the frozen writer's mode, forwarding all other current native guards without reading/copying NODE_OPTIONS or hiding future guard keys. No new global fetch/environment/dispatcher mutation, process-mode rewrite or hook is allowed. Preserve only the frozen native guard's already accepted static-token deletion and retry-zero environment effects; the wrapper adds none.

Pass a local fetch wrapper to the frozen runner. Accept only its existing confined normal/held verification GETs, unchanged strong If-Match and closed request options; add `Accept-Encoding: identity` explicitly. SDK metadata/signing requests and the ordinary/held PUT adapter are unchanged. Reject ANY Content-Encoding response header, including empty/identity/unknown/compound values, before returning the response. A request header alone is never acceptance. The wrapper must cancel bodies it rejects or receives after abort, with caught nonawaited cancellation; the old runner cannot track a body it never receives.

Keep the frozen verifier's exact200, Content-Length, strong GET/metadata ETag equality, expected MIME, URL, bounded full-body EOF/hash and all deadlines/context/late-result checks. Require a present exact confined response URL in the wrapper. Never fall back to range, relaxed length/tag, decoded encoded-body acceptance, retry or a second key. The closed result changes only schema; preserve all phase/check/race/evidence/reconciliation values. No result projection can upgrade failure or inconclusive evidence.
