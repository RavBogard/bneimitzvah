## 1. Route designs

**Common rules.** Every route goes through the existing `/api/public/` allowlist (`src/server/http/public-reading.ts:28-41`) and keeps what is already there:
- GET only;
- a closed, canonical query (`canonical()`, `:67-79`);
- `resolveTenant` (CRC only);
- `noindex`;
- `cache-control: public, max-age=300`, with `vercel-cdn-cache-control` per route;
- failures as `no-store` JSON;
- the 2 MiB body guard (`:51-56`);
- the firewall rule of 120 requests a minute per IP, which already covers the prefix (STATE line 51).

**Change to `canonical()`.** Value length becomes a per-key limit: `ref` 1000 characters, everything else 80 as now (`:73`). The route table changes from one keyset per path to a list of allowed keysets. The query must match exactly one keyset, in its order.

### 1.1 Ref-keyed reading (the §3.11 contract; PR A)

| Path | Keysets (in order) | Body for the `ref` form | CDN |
|---|---|---|---|
| `/api/public/reading` | `[date]` (unchanged) · **`[ref, kind]`** | `{ ref, kind, passage: {kind, ranges, verseCount, pages:[{offset,first,last}]}, listening:{pocketTorah} }` | 3600 |
| `/api/public/text` | `[date,kind,offset]` · **`[ref,kind,offset]`** | Today's body with `ref` in place of `date` (`studyPageView`) | 86400 |
| `/api/public/reference/short` | `[date,kind,offset]` · **`[ref,kind,offset]`** | `{ kind, ref, page:{offset,nextOffset,totalVerses,references} }` | 86400 |
| `/api/public/word-aids` | `[date,kind,verse]` · **`[ref,kind,verse]`** | As today, with `ref` | 86400 |
| `/api/public/word-details` | `[date,kind,verse,word]` · **`[ref,kind,verse,word]`** | As today, with `ref` | 86400 |

`passage` is exactly the `PublicPassage` shape the weekly route already serves (`src/server/public-reading/service.ts:33`), and the paging is identical. One parity test pins this (§6). The 1.5 offline packer then needs only `urls.ts`.

**Validation.** It runs in the cheap pre-check, before any runtime or database opens (`public-reading.ts:93-97`).
- **`canonicalReadingRef(ref, kind)`** goes in a new `src/lib/readings/reading-ref.ts`.
  - `readingSegments` split on exactly `"; "`.
  - Each segment must equal its own `hebcalRef` re-serialization (`leyning.mjs:15-21`): `Genesis 12:1-20`, never `12:1-12:20`.
  - At most 32 segments and 1000 characters.
  - Then `expandReadingRanges(..., TANAKH_VERSE_COUNTS, 1000)` (`ranges.ts:34-71`).
- **`kind=torah`** requires every segment in a Torah book. One book, ordered, is already enforced at `ranges.ts:52`.
- **`kind=haftarah`** requires every segment in `NEVIIM_BOOKS` (`src/lib/readings/commentary.ts:12-13`). Ketuvim is refused (see D1).
- These limits match the 1.4 `saved_reading` checks (accounts plan lines 47-49), so anything a member can save, this route can open.

**Service.** `createPublicReadingService` is refactored so `text`, `wordAids`, `wordDetails` and `shortReferences` take a resolved `Plan` (`service.ts:44-53`).
- The date methods resolve a Plan through `publicPlans(snapshot)` as now (`:55-62`).
- New `*ByRef` methods resolve it through `plan(kind, segments)`.
- `reading?ref` needs no upstream call: the passage is computed locally.
- The header invariant ("never from a caller-supplied range", `:19-27`) is rewritten as: caller ranges are accepted only in canonical, bounded form.

**Failure modes.**
- A bad or non-canonical ref, a kind mismatch or Ketuvim: 400.
- A mixed keyset (`date` and `ref` together): 400.
- An offset that is not a page start: 400 (`pageOffset`).
- Upstream text failure: 503, no-store.
- PocketTorah not released: short returns 404, as today.

### 1.2 `/api/public/translations?verse=<Book c:v>` (Compare; PR B)

**Upstream.** Two calls in parallel, each with a 5 s deadline and a 1 MiB cap:
- `v3/texts/<verse>?version=english|all&fill_in_missing_segments=0&return_format=default`;
- the Targum:
  - for Torah, `Onkelos <Book> c:v`;
  - for Nevi'im, `Targum Jonathan on <Book> c:v`;
  - both with `version=hebrew&version=english`.

**Projection.** Text goes through `sefariaRuns` (`src/server/study/sefaria-runs.ts`). The response is:

```
{ verse,
  translations: [{ title, license, licenseLabel, credit, url, runs }],
  targum: { work: "Onkelos"|"Targum Jonathan",
            aramaic: Edition&{runs} | null,
            english: Edition&{runs} | null } | null }
```

What is filtered out:
- JPS 2023, because it is already shown (match on `JPS2023.versionTitle`, `src/server/study/versions.ts:9`);
- empty text;
- any title ending `[xx]` where xx is not `en`;
- duplicate titles.

Order is Sefaria's. Caps: 40 translations, 16 KiB per text, 256 KiB response.

**Other rules.** `verse` must match `Book c:v` in Torah or Nevi'im and be in range. CDN keeps the answer 30 days. Failure is 503, no-store. If one of the two upstream calls fails, the other still answers, with the missing part `null` and a CDN time of 1 hour.

### 1.3 `/api/public/related?verse=<Book c:v>` (the shelf; PR C)

**Upstream.** The existing hardened transport, `createSefariaMetadataReader` (`src/server/study/sources/sefaria-metadata.ts`). It gains one method, `shelfLinks(verse, signal)`, using the same URL as `related()` (`:69-71`). Its bounds: 10 s total, 5 s idle, 2 MiB, 4096 rows.

**Parser.** A new `parseShelfLinks` in `src/server/study/shelf.ts`.
- It reuses `metadata.ts`'s anchor rule (`anchorRef` or `anchorRefExpanded` contains the verse, `:50-58`) and its `plain()` hygiene.
- It keeps `index_title`, `collectiveTitle.en/he`, `category`, `sourceRef` and `compDate`.
- It leaves the existing `parseRelatedMetadata` and catalog hash alone, because signed-in assignments depend on them.

Response:

```
{ verse, sefariaUrl,
  groups: [{ key, label, count,
             works: [{ title, heTitle, dates, category, curated,
                       items: [{ ref, segments }], more }] }] }
```

- Groups: commentary, midrash, halakhah, talmud, targum and other.
- `dates` is `[from, to]` or null, taken from `compDate`.
- `segments` counts the comments folded into one item.

**Collapse rule.** When every ref of a work is `<index_title> c:v:n` under one parent, the work becomes **one** item, `<index_title> c:v`, so Ramban's three comments open as one text. Otherwise each ref is its own item.

**Caps:**
- at most 50 items per work, with the rest counted in `more` (Exodus 12:2 has one work with 133 links);
- at most 400 works;
- at most 384 KiB of response.

Measured compact size: 54–61 KB for 716–863 links.

CDN keeps the answer 7 days. Failure is 503, no-store.

### 1.4 `/api/public/source?ref=<Sefaria ref>` (open one shelf item; PR C)

**Upstream.** `v3/texts/<ref>?version=hebrew&version=english&fill_in_missing_segments=0&return_format=default`, with a 5 s deadline and a 1 MiB cap. It takes Sefaria's default edition in each language. There is no pinning, because there are hundreds of works.

**Text shapes.**
- A string means one segment; an array of up to 64 strings means a section or range. Anything deeper is 404 (`unsupported`).
- Warnings 101–104 are allowed only under the `hebrew` or `english` keys.
- Segments pair by index, as in `validateCommentaryPayload`.

**Response.**

```
{ ref, sefariaUrl,
  segments: CommentaryComment[],
  editions: [{ language, title, license, licenseLabel, credit, url }] }
```

Total size is at most 256 KiB.

**Ref grammar.** At most 256 bytes. It is the `plain()` set (no `<>`, controls or bidi characters), restricted to `[\p{L}\p{N} ,.'’()\-:;"]`, and it must end in a numeric or daf address (`\d+[ab]?(:\d+)*(-\d+[ab]?(:\d+)*)?`).

**Failure modes.**
- Sefaria 404 or 400: 404 no-store. The UI shows "Open on Sefaria".
- Timeout or a bad shape: 503.

CDN keeps the answer 30 days.

**This is a bounded proxy of public Sefaria texts.** It is the first public route whose URL space is not tied to the calendar (`src/lib/readings/public-shabbat.ts:4-8` explains why every route so far was). I rejected the alternatives (§4). Cost is covered by the CDN plus the per-IP limit. The route goes to the adversarial reviewer.

### 1.5 `/api/public/commentary` (PR B change)

- A 404 whose JSON `error` starts "We have no text for" becomes an empty chapter: `verses:{}, editions:[]`, CDN-cached 1 day.
- Any other non-200 stays 503.

## 4. Tradeoffs rejected

- **A live Hebcal "next date of this parashah or holiday" selector.**
  - Holidays fall on weekdays, outside `publicShabbat`.
  - `publicPlans` hides the Torah unless the classification is regular (`service.ts:57`).
  - "multiple" days answer nothing.
  - There would be no stable range key for 1.4 saved readings or 1.5 packs.
  - Instead: a static numeric catalog (§5, A1).
- **Relaxing `expandReadingRanges` so a Torah ref can cross books** (holiday maftirs). It is shared with assignment validation (`ranges.ts:52`). Instead, a named reading is a list of passages.
- **Counts on the closed "More on this verse" row.** Counts need one links fetch (up to 1 MB upstream) per verse in view. A Study page of up to 100 verses would also crowd the 120-a-minute per-IP limit alongside text and commentary requests. Instead, counts appear after the first open (D3).
- **`with_text=1` for the spec's "first line".** It is about 3 times the bytes, and every snippet would need its own credit. Rows show the work, its composition dates and the citation.
- **Pinning editions for every shelf work.** Instead: Sefaria's per-language default, credited from the returned metadata.
- **Binding `source?ref` to the verse's link list,** with a signed token or a database-cached catalog. That means a new cache table or migration, or a second 1 MB fetch on every open. Instead: grammar plus CDN plus the rate limit, with adversarial review.
- **Reusing the signed-in source reader** (`src/server/study/source-content-service.ts`). It is POST, student-scoped and catalog-hash-bound, and refuses everything that isn't Public Domain or CC0 (`sources/content.ts:19-21`). It is left untouched.
- **Refactoring the four existing bounded-fetch copies into one.** That is churn in reviewed code. Only the new readers share a new helper.
- **A permanent third column for the panel.** It wastes width when closed. The column opens with the panel, and the scroll position is anchored.
- **Serwist, a new dependency, or a server cache table.** Not needed: the CDN is the cache.

## 7. Risks and how each is checked

- **Sefaria latency and limits.** Genesis 1:1 links took 4.6 s against a 10 s budget. There is no published rate limit.
  - Mitigation: long CDN times (7 and 30 days) and user-initiated fetches only, with no prefetch.
  - Checked by the live probes after deploy and by watching runtime errors for 503 rates.
- **Huge link lists.** Bounded at 2 MiB and 4096 rows upstream, and 384 KiB and per-work caps in our response. Unit tests cover the caps.
- **Our own 120-a-minute limit.** Study with three works and up to 8 chapters is at most about 27 requests on a page. Shelf and Compare are on demand. A 429 shows the quiet failure line.
- **RTL and bidi.** Explicit `dir` on every block, `<bdi>` for refs, bidi controls stripped (`sefaria-runs.ts:19`). The Playwright checks include a Hebrew-in-English fixture.
- **Licence credit correctness.** We show what Sefaria states, normalized by `licenseLabel`. "Copyright:" and "unknown" are shown, not guessed. Ruling 10(2) withdrew the "never shown in place" tier, which covered copyrighted editions. Unit tests cover the label mapping.
- **Commentary data drift** (complex flags, titles, licences). The strict validator turns drift into a 503 for that work only. The live sweep runs before merge.
- **Public proxy and URL space growth** (ref, source). Cost estimate: under $1 a month added, because of CDN hits and Fluid billing only active CPU. It gets a GATE line as spend logged under $10. It also gets an adversarial pass.
- **Named-catalog errors** (customs, overridden haftarot). The script refuses rather than guesses, and the parity and spot tests cover it. The executor reviews the generated file by eye in the PR.
- **1.2 is uncommitted** in `bneimitzvah-lens`. A3, B3 and C3 must not start until it merges.

## 8. Decided here (log in STATE when built)

1. Ref keysets are `[ref,kind]` and `[ref,kind,offset]`. The ref is canonical hebcal form joined by "; ", up to 1000 characters, 32 segments and 1000 verses, Torah or Nevi'im only.
